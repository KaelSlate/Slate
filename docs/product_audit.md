## Краткое резюме

Ядро продукта в отличной форме: цикл «хоткей → пилюля → парсер → таймлайн → чекбокс»
собран, undo есть, экспорт есть, онбординг учит одной вещи, тесты зелёные, архитектура
скорости (Rust-store, zero-copy FFI, гранулярные нотификаторы, отдельное окно пилюли)
реально топовая для Flutter/Windows. Отдельное окно пилюли закрыло целый класс багов —
это видно и по коду, и по тому, что матрица e2e переписана 7/7.

Но до выдачи 10–15 **западным** тестерам есть два блокера и один коварный риск:

1. **Провал открытия базы — тихий, и превращается в запись в пустоту** (B1). Один такой
   случай = «Slate потерял мои задачи» = конец доверия и теста.
2. **Парсер времени не понимает английский** («5pm», «at 5») — а волна 1 это EN-тестеры.
   Главная магия продукта для них молчит (A1).
3. **База лежит в Documents**, которые у половины Windows-мира редиректятся в OneDrive —
   классический сценарий коррапта SQLite и конфликтов (B2).

Всё остальное — полировка и осознанное «потом».

## A. Карта пути пользователя (UX)

### A1. Парсер времени: нет английских форм — блокер для волны 1
**Что.** `nlp_parser.rs` понимает `14:00`, `14.00`, диапазоны, и русские «в 5», «на 14»,
«9 вечера», «5 часов». Английских `5pm`, `at 5`, `noon` — **нет** (проверено по коду и
по отсутствию тестов). Даты EN есть (today/tomorrow/monday/jul 15), времена — нет.
Западный тестер печатает `gym at 6pm` → время не распознано, «at 6pm» остаётся мусором
в заголовке. Ядро обещания («выдохнул — само разложилось») для целевой аудитории волны 1
не срабатывает в самой частой форме ввода: США думают в 12-часовом формате.
**Критичность.** Блокер для волны 1 (для волны 0 с близким RU-человеком — нет).
**Направление.** Добавить в парсер `N pm/am` (слитно и раздельно), `at N[:MM]`, опционально
`noon/midnight`. Изолированная правка одного файла + тесты по образцу существующих.
**Уверенность.** Точно.

### A2. Правило 60 секунд — выполняется, с одной оговоркой
**Что.** Welcome учит ровно одной вещи — реальному зарегистрированному чорду
(`hotkeyLabel`, не хардкод — тест это проверяет). Demo-неделя даёт анатомию экрана без
туториального цирка. Лестница уроков (invite/accelerator, ретирование по собственному
мастерству, бюджет 3 показов) — образцовая, лучше большинства коммерческих продуктов.
**Оговорка:** если заняты все три чорда (Alt+Space, Ctrl+Alt+Space, Ctrl+Alt+S), хоткей
тихо отключается, а `hotkeyLabel` остаётся дефолтным «Alt+Space» — welcome и трей
показывают чорд, который **не работает**. Вероятность мала, но это тихий провал главного
обещания.
**Критичность.** Потом (низкая вероятность), но держать в голове при жалобе «хоткей не работает».
**Направление.** При полном провале регистрации — честное состояние в welcome/трее
(«хоткей занят другой программой») вместо ложного чорда.
**Уверенность.** Точно по коду.

### A3. Синтаксис захвата нигде не преподаётся
**Что.** Плейсхолдер пилюли — «Type a task...». Что можно `15:00`, `#tag`, `!!`, `tomorrow` —
юзер узнаёт только случайно (чип destination показывает результат, но не подсказывает
возможности). Тестер, который ни разу не набрал время текстом, не увидит магию парсера
вообще — и в интервью скажет «ну, обычный todo».
**Критичность.** Важно для честности теста ретеншена.
**Направление.** Самое тихое: ротация плейсхолдера примерами («Call mom tomorrow 15:00»,
«Draft #work !!») первые N вызовов пилюли — по духу совпадает с существующей лестницей
уроков (и Shift+Enter-подсказка в пилюле уже работает так же: session-scoped, сдаётся
после 4 вызовов).
**Уверенность.** Точно (что не преподаётся); направление — на твой вкус.

### A4. Обнаруживаемость действий — закрыта
Проверено по коду: удаление/редактирование — hover-шельф на каждой карточке во всех видах
(неделя, месяц, день, инбокс, peek); «+» на ховере ячейки дня; Inbox-кнопка в хедере +
клавиша I; WEEK/MONTH — переключатель в хедере + V; зум — invite «Ctrl + scroll a day»;
drag — invite после первого зума; Esc-приоритеты (инбокс → текст → зум-аут) продуманы;
Ctrl+Z с тостом «Deleted — Ctrl+Z to undo» учит в момент страха. Мышиный и клавиатурный
пути не расходятся: у каждого клавиатурного действия есть мышиный эквивалент. Дешёвого
drag нет (mouse исключён из dragDevices, DragSource поднимает карту после 5px). Это
сильная сторона — придраться не к чему.

### A5. Мелочи (потом)
- EN-сокращения дней: `mon..fri` парсятся, `sat`/`sun` — нет (точно, по таблице WEEKDAYS).
- Redo нет (Ctrl+Z есть, Ctrl+Shift+Z зарезервирован комментарием) — потом.
- Счётчики «SCHEDULED 3 / TO SCHEDULE 5» в day view — нейтральная навигация, вины не
  создают (знаменателя-упрёка нет) — ок по компасу.

## B. Сохранность локальных данных

### B1. Провал открытия базы: тихий + последующие записи уходят в пустоту — блокер
**Что.** Если `init_engine` вернул −1 (ключ DPAPI умер/сменился профиль, коррапт файла,
файл заблокирован), `TaskState` молча подставляет 5 стаб-задач «Sample task N»
(`task_state.dart:139-144`) и приложение **выглядит работающим**. Двойной удар:
1) юзер видит вместо своих задач образцы → паника «всё пропало» (хотя файл цел на диске);
2) всё, что он вводит дальше, пишется только в память (db-writer не запущен) и **реально
теряется** при выходе. Первое впечатление умирает ровно от такого.
**Критичность.** Блокер. Это единственное место, где продукт может честно потерять данные.
**Направление.** Явное состояние «база не открылась» вместо стабов: не давать писать в
пустоту, показать путь к файлу, предложить «создать новую базу (старая сохранится рядом)».
Плюс тост/баннер, если движок жив, но `ENGINE_READY` false.
**Уверенность.** Точно (по коду; сам сценарий ключа DPAPI — «надо проверить»: снести
запись `slate_db_key` из secure storage при существующей базе и посмотреть, что увидит юзер).

### B2. База в Documents = OneDrive-рулетка — важно
**Что.** `getApplicationDocumentsDirectory()` на Windows — это Documents, который у
огромной доли машин редиректится в OneDrive. SQLite в WAL-режиме внутри синхронизируемой
папки — известный генератор корраптов (облачный клиент лочит/подменяет `-wal`/`-shm`,
делает conflicted copies). Плюс видимая папка `Documents\slate_data` + экспорты в корень
Documents = мусор на глазах у юзера.
**Критичность.** Важно (до раздачи незнакомцам — у тестеров машины непредсказуемы).
**Направление.** Переезд в `%LOCALAPPDATA%` (`getApplicationSupportDirectory`) с
одноразовой миграцией существующего файла. Экспорты можно оставить в Documents — они
для человека.
**Уверенность.** Путь — точно; частота OneDrive-редиректа у будущих тестеров — не знаю,
но класс риска известный.

### B3. Авто-бэкап JSON — дешёвая страховка всего сразу
**Что.** Ключ SQLCipher живёт в DPAPI и умирает с профилем Windows — закон это знает
(«Экспорт всегда доступен»), но экспорт ручной: тестер его не нажмёт ни разу.
**Направление.** Раз в день (или на quit) писать тот же `buildExportJson` в
`slate_data/backup/` с ротацией на 5–7 файлов. Закрывает частично B1, B2 и смерть ключа:
задачи — простой текст рядом с базой. Три строки кода вокруг уже существующего экспорта.
**Критичность.** Важно. **Уверенность.** Точно.

### B4. Что уже хорошо (зафиксировать и не трогать)
- SQLCipher: raw-key без PBKDF2 (осознанно, ключ полноэнтропийный), миграция со старого
  KDF-ключа с бэкапами `.pre-rawkey.bak` — образцово.
- WAL + `synchronous=NORMAL`: при power-loss теряются миллисекунды, БД не коррапится.
- Асинхронная очередь записи дренится мгновенно (Condvar), graceful shutdown дренит
  остаток + checkpoint; краш теряет максимум последние мс.
- Zero-panic политика + panic hook в `rust_panic.txt` рядом с крашлогом.
- Undo на 50 шагов с полным снапшотом и восстановлением позиции в дне.
- Миграции схемы additive через `user_version` 1→3 — безопасно для старых БД.
- Supabase честно выключен: ключи только через `--dart-define` (в коде и сборке их нет),
  без них sync-поток даже не спаунится. Проверено грепом — хардкода нет.

### B5. Мелочи (потом)
- **WM_ENDSESSION не обрабатывается** в раннере: при выключении Windows процесс умирает
  без `ffi_shutdown_engine`. Реальная потеря ≈ 0 (очередь дренится асинхронно, WAL
  реиграется при следующем старте), но одна ветка в `WndProc` сделала бы выключение
  формально чистым. Надо проверить замером, не теряется ли что-то на живой машине.
- `prefs.json` пишется fire-and-forget без temp+rename: краш в момент записи → сброс
  онбординга/уроков (не задач). Мелочь.
- Кэш нотификаторов `_tasksByDateNotifiers`/`_tasksByHourNotifiers` растёт на каждый
  посещённый день и не чистится — копеечная утечка длинной сессии.
- Мёртвый код синка (`sync_engine.rs`, `ureq`) остаётся в DLL при выключенном Supabase —
  не активен, просто лишняя поверхность.

## C. Ощущение продукта: скорость, плавность, отклик

### C1. Архитектура скорости — сделана правильно (по коду)
- Rust-store: HashMap + BTreeMap-индекс по дням, O(1)/O(log N), чтения под RwLock.
- Zero-copy FFI: `#[repr(C)]`-структуры, без JSON на горячем пути; Caller-Frees соблюдён
  (15 `finally` в мосте).
- Гранулярная реактивность: `tasksForDateNotifier`/`tasksForHourNotifier` + `mutationTick`
  вместо полного ребилда вида на каждый тик — правильный паттерн.
- BackdropFilter дисциплинирован: живой блюр только в инбокс-дровере (16px, пока открыт)
  и в пилюле; карточки — плоские полупрозрачные (сознательный отказ от per-card блюра).
- 20 × RepaintBoundary в нужных местах; «лазер времени» тикает 1 Гц и только в day view.
- Отдельное окно пилюли всегда живо → summon без создания окна = мгновенный. Это
  архитектурно лучший вариант, морф-сага закрыта.
- Старт: движок, шрифты, prefs и окно инициализируются параллельно; warmup-вуаль
  компилирует шейдеры за 3 кадра с watchdog 4с — вуаль не может застрять.

### C2. Что могу оценить только профилированием — не знаю, пока не замерим
- Реальный FPS недели/месяца на слабом железе (интеграшка, 1366×768 и 4K): Skia на
  Windows — не Impeller, теней и градиентов много. **Замерить:** `flutter run --profile`
  + DevTools timeline на самой слабой доступной машине; PresentMon для DWM-статтера;
  отдельно скролл таймлайна дня и drag с 30+ задачами в день.
- Стоимость инбокс-блюра 16px на 4K-мониторе при открытом дровере.
- Один известный transient: 1-кадровый рывок focused-windowed summon у пилюли (DWM тянет
  живую поверхность) — уже задокументирован, гейт «глаза юзера».
- Cold start на HDD-машине (DLL + SQLCipher open + 3 шрифта) — по коду должно быть <1с,
  надо цифру.

### C3. Потом
- 308 analyze-info (`withOpacity` → `withValues`) и clippy-линты — гигиена перед
  привлечением любых внешних глаз к коду.

## Отдельно: «чтобы никто не вскрыл код» (вопрос фаундера, вне промпта)

Честная рамка: **локальное приложение невозможно защитить от вскрытия абсолютно** — оно
целиком в руках пользователя. Цель — поднять цену копирования, а не построить ДРМ.
Состояние и что сделать:

| Слой | Сейчас | Рекомендация |
|------|--------|--------------|
| Rust DLL | `strip=true, lto, codegen-units=1, panic=abort` — символы вырезаны, декомпиляция даёт голый ассемблер. Экспорты `ffi_*` видны (неизбежно для FFI) | Ничего не менять — уже хорошо |
| Dart-код | AOT-снапшот (`data/app.so`) — не исходники, но **без обфускации**: имена классов/методов читаются, структура приложения восстанавливается | Перед публичной раздачей: `flutter build windows --release --obfuscate --split-debug-info=symbols/`. **Обязательно** хранить `symbols/` — иначе крашлоги тестеров станут нечитаемыми |
| Секреты | В бинаре секретов нет: Supabase-ключи не хардкожены (проверено), БД зашифрована, ключ в DPAPI юзера | Так и держать: ключи только через `--dart-define`, и то не для MVP |
| Загрузка DLL | Мост ищет `slate_core.dll` и по относительным путям, включая CWD — теоретическая DLL-podmena при запуске из чужой папки | Мелочь: в release оставить только путь рядом с exe. Потом |
| Реальная угроза №1 | Не реверс, а **SmartScreen/антивирусы**: неподписанный exe с глобальным хоткеем + автозапуском + DLL = портрет спайвари | Уже в законах манифеста: подпись кода + VirusTotal до волны незнакомцев. Это важнее любой обфускации |
| Пакеры/VMProtect | — | **Не делать**: триггерит антивирусы, убивает доверие, ценности для MVP ноль |

## Приоритизированный топ до выдачи

**Закрыть до волны 0 (один близкий человек):**
1. **B1** — честный отказ вместо тихих стабов + запрет записи в пустоту. Единственный
   сценарий невосполнимой потери данных и доверия.

**Закрыть до волны 1 (10–15 EN-тестеров):**
2. **A1** — `5pm` / `at 5` в парсере. Без этого ядро магии молчит для всей волны.
3. **B2** — переезд базы из Documents (OneDrive) в LocalAppData с миграцией.
4. **B3** — тихий авто-бэкап JSON с ротацией.
5. **A3** — ротация плейсхолдера: научить синтаксису, не открывая рта.
6. Подпись кода + VirusTotal + `--obfuscate` со складом symbols (законы блока 10 + реверс).

**Осознанно потом:**
- A2 (ложный чорд при полном провале регистрации), sat/sun, redo, WM_ENDSESSION,
  атомарная запись prefs, чистка кэша нотификаторов, clippy/analyze-гигиена,
  вырезание мёртвого синк-кода из DLL.
- Профилирование на слабом железе — сделать при первой возможности достать такую машину;
  до этого не голосовать за микрооптимизации.

**Не применимо на этой стадии** (одной строкой, чтобы не возвращаться): аккаунты/облако,
XSS/CSRF/веб-поверхность, масштабирование, платежи, телеметрия (заменена интервью +
локальным крашлогом — по закону).
