# Global Quick Capture — дизайн

Дата: 2026-07-03. Статус: утверждено делегированием (компас §1, §8.2 — выбор за Claude на уровне Apple+).

## Проблема

Главный клин продукта — «хоткей из любого места ОС → выдохнул мысль → вернулся к работе за 2 секунды» — отсутствовал: пилюля вызывалась только клавишей `C` внутри приложения. Это разрыв №1 между тезисом файла-компаса и продуктом.

## Решение за 30 секунд

Глобальный хоткей **Ctrl + Alt + Space** (работает, пока Slate запущен — свернут или в фоне). Из любого приложения: пилюля — та же самая, что в дне, — плавно раскрывается из середины в обе стороны внизу по центру активного монитора, поверх всех окон. Ввод → Enter → задача мгновенно в Rust-движке → пилюля растворяется → фокус сам возвращается в браузер. Esc или клик мимо — то же исчезновение без следа.

## Ключевые решения и почему

### 1. Хоткей: Ctrl + Alt + Space

Перебор всех кандидатов против инструментов племени (VS Code, IntelliJ, Chrome, Figma, Office, PowerToys):

- `Ctrl+Space` — автодополнение в каждом IDE. Украсть его глобально = убить продукт для разработчиков. Нет.
- `Ctrl+Shift+Space` — parameter hints в VS Code и IntelliJ. Нет.
- `Alt+Space` — системное меню окна Windows + дефолт PowerToys Run. Нет.
- `Win+Space` — переключение раскладки. Нет.
- **`Ctrl+Alt+Space` — свободен во всех инструментах племени, берётся одной левой рукой (большой палец + мизинец), читается как «усиленный пробел» = «вдох».** Если занят другим приложением (RegisterHotKey вернёт отказ) — тихий fallback на `Ctrl+Alt+S`.

### 2. Архитектура: морф главного окна (одно окно, один движок)

Оverlay — это само главное Flutter-окно, временно преобразованное: скрыть → уменьшить до полосы пилюли → прозрачный фон (flutter_acrylic) → always-on-top, без таскбара → низ-центр монитора с курсором → показать с фокусом (RegisterHotKey даёт процессу право на SetForegroundWindow). После — обратное восстановление точного прежнего состояния (bounds / minimized / visible-без-фокуса).

Почему не альтернативы:
- `desktop_multi_window` (второе окно = второй Flutter-движок): +50–100 МБ RAM постоянно, плагины в под-окне не регистрируются автоматически, известные баги фокуса клавиатуры на Windows — смертельно для поля ввода.
- Нативное Win32-окно со вторым engine-view: недели работы ради того же результата.

Выигрыш морфа: Rust-движок в том же процессе (нулевой IPC, задача создаётся мгновенно и TaskState обновляется вживую), пилюля — тот же виджет `SmartDayInputWidget` (пиксельная идентичность, та же подсветка токенов, те же шрифты уже прогреты).

Состояния:
- Приложение в фокусе → хоткей открывает обычную внутреннюю пилюлю (как `C`). Никакого морфа.
- Приложение не в фокусе / свернуто → морф в overlay.
- Повторный хоткей при открытом overlay → dismiss (toggle).
- Потеря фокуса окна (клик в браузер) → dismiss.

Восстановление: запоминаем `{bounds, wasMinimized, wasVisible}` до морфа. После: hide → выключить прозрачность → вернуть bounds → если был minimized — вернуть в minimized; если был видим — показать БЕЗ активации (фокус остаётся у браузера); прозрачный эффект включается только на время overlay (в обычном режиме нулевая цена композиции).

### 3. Материал пилюли в overlay

Flutter не может размыть чужие окна (BackdropFilter сэмплирует только свою сцену), а window-acrylic на Win10 капризен. По правилу компаса («тот же эффект сплошным полупрозрачным фоном — давай дешевле»): тёплый графит ~0.93 непрозрачности + тот же LiquidGlassPainter (rim light, inner shadow, focus ring) + те же тени. Бонус: без BackdropFilter вход можно анимировать scale+opacity свободно — гоча «мигание блюра» не применима.

### 4. Анимация входа — «раскрытие из середины»

- scaleX 0.55 → 1.0 пружиной (stiffness 420, damping ratio 0.86, устаканивается ~300 мс) с `Alignment.center` — расширение из центра в обе стороны;
- scaleY 0.90 → 1.0 той же пружиной;
- opacity 0 → 1 за первые ~110 мс (easeOut);
- подъём translateY +10 → 0.
- `filterQuality` не-null на время движения, null в покое (железное правило Transform.scale на живом тексте).
- Выход: 150 мс, scale → 0.96 + fade → hide окна. Submit: существующий мягкий пульс, затем выход.
- Окно показывается только после того, как Flutter отрисовал кадр в новом размере (никакого мусорного первого кадра). Цель: < 100 мс от нажатия до видимой пилюли.

### 5. Семантика назначения (эталонная таблица)

| дата | время | назначение |
|---|---|---|
| нет | нет | **Inbox** |
| нет | есть | **Сегодня в это время**; если время уже прошло — **завтра** (roll-forward) |
| есть | есть | конкретный день + время |
| есть | нет | конкретный день, нераспределено (без привязки к часу) |

Roll-forward — единственное отличие от обеих предложенных таблиц и оно строго лучше: задача «сегодня в 9:00», созданная в 18:00, рождается просроченной = чувство вины (главный враг по компасу). Todoist/Fantastical делают так же. Прозрачность гарантирует **лейбл назначения** внутри пилюли (справа, приглушённый): `Inbox` / `Today 14:00` / `Tomorrow 09:00` / `Fri · Jul 17`. Меняется анимированно по мере ввода — пользователь всегда видит, куда уйдёт задача, до Enter.

Внутренняя пилюля (C): распознанная дата в тексте теперь тоже уважается (иначе «завтра» стёрлось бы из заголовка, а задача легла бы не туда). Нет даты → просматриваемый день, как раньше. Roll-forward внутри дня НЕ применяется (там день выбран явно).

### 6. Даты в Rust-парсере (общие для обеих пилюль)

Новые паттерны (RU полностью + EN ядро): `сегодня/today`, `завтра/tomorrow`, `послезавтра`, дни недели полные и короткие с предлогом и без (`в пятницу`, `пт`, `friday`, `fri`). Резолв: ближайшее вхождение, включая сегодня («в четверг», сказанное в четверг, = сегодня — как Fantastical), числовые `15.07`, `15.07.2026`, месяцы прописью `15 июля` / `jul 15`.

ABI: в конец `CParseResult` добавляются `date_kind: u8` (0 none / 1 offset / 2 weekday / 3 explicit) и `date_a, date_b, date_c: i64` (offset дней | weekday 1–7 | y, m, d). Rust остаётся чистым «текст → токены»; резолв в реальный день (таймзона, «ближайшее вхождение», roll-forward) — в Dart (`CaptureDestination`), на каждый кейстроук для лейбла и в момент Enter для истины. После изменения Rust: `cargo build --release` + копирование `slate_core.dll` в корень — обязательно (иначе Access Violation).

### 8. Границы (честно)

- Хоткей живёт, пока Slate запущен. Трей-резидентность и автостарт с Windows — отдельная следующая задача (не тянем в эту).
- Реального размытия браузера под пилюлей нет (ограничение платформы; компас это санкционирует).
- Если окно приложения было развёрнуто и видно на экране — на время захвата оно исчезает и возвращается без фокуса (краевой случай; племя держит планировщик свернутым).
- Мобильных/облачных следствий нет; Supabase не затрагивается.

### 9. v2 — трей-резидентность и полировка (2026-07-06, реализовано)

- **Хоткей: Alt+Space** (двухклавишный «summon» индустрии: Spotlight/Raycast/PowerToys Run). hotkey_manager не сообщает об отказе RegisterHotKey, поэтому свобода аккорда проверяется пробингом через user32 напрямую; цепочка: Alt+Space → Ctrl+Alt+Space → Ctrl+Alt+S. Зарегистрированный аккорд виден в тултипе трея.
- **Трей + автостарт**: X прячет в трей (движок и хоткей живут); Quit — только из меню трея (с Rust-flush). Меню: Open Slate / Quick Capture / Launch at startup (галка, дефолт ON, пишется в prefs) / Quit. Автостарт = HKCU Run с флагом `--hidden` (при логине — только трей и хоткей, окна нет). Путь в реестре само-освежается на каждом запуске.
- **Slate в фокусе → in-app capture**: сцена ложится ПОВЕРХ MainScreen (Stack в корне), окно не трогается вообще — исчез «Slate прикрывается и разворачивается заново». Конфликт с пилюлей дня: если C-пилюля открыта, хоткей — no-op; in-app сцена ставит `isComposingTask` (модальность как у пилюли дня); при морфе из фона затирается возможный залипший флаг.
- **Белая вспышка — корень и фикс**: окно показывалось после ресайза до того, как Flutter presented первый кадр в новый swapchain (неинициализированный буфер компонуется белым; скрытые окна кадры не презентуют — отсюда «иногда»). Фикс: все show/hide-переходы идут под `setOpacity(0)`, раскрытие только после 2 presented-кадров. Верифицировано burst-захватом: 4 перехода × 20-24 кадра, максимум яркости 44/255 — ни одного яркого кадра.
- **Enter vs Shift+Enter (глобальная пилюля)**: Enter = выдох → задача → растворение (Raycast/Spotlight/Todoist-паттерн «one breath out»); **Shift+Enter = rapid dump** — создать и оставить пилюлю открытой для следующей мысли. Одиночный TextField не даёт onSubmitted на Shift+Enter надёжно — перехват синхронно на `focusNode.onKeyEvent` (floating-режим). Внутренняя пилюля дня остаётся multi-entry по Enter (там сессия планирования, другой контекст — это осознанно разные поведения).
- **Парсер**: + «через N дней/недель», «через неделю», “in N days”, “in a week” (guard: «через 3 дня» — длительность, а не «3 часа дня»).
