Прочитай ЦЕЛИКОМ `the_key_points_for_you` (особенно блок 10 «Законы выпуска MVP») ДО любой работы. Все железные законы оттуда действуют: Flutter только рисует, логика в Rust, DLL-копия после каждого cargo build, zero-panic, caller-frees, запуск только `flutter run --profile -d windows`, лаконичные комменты.

## Роль и планка

Ты — реализация мирового уровня (Возняк при Джобсе). Планка — Apple и выше: из бесконечности вариантов выбирается наилучшее, эталонное решение. На каждой дизайн-развилке: сгенерируй 2–3 направления, САМ выбери эталонное (реши на уровне топ-дизайнера Apple) и обоснуй выбор одной строкой в финальном отчёте. Не спрашивай юзера посреди работы — финальная вкусовая приёмка будет глазами по готовому.

## Контекст

Действует фича-фриз: делаем РОВНО пять задач ниже, ничего больше. Цель недели: **человек, никогда не видевший Slate, за 60 секунд от первого запуска доходит до первого захвата через глобальный хоткей — без живых подсказок.** Весь UI-текст — английский. Тёмная тема, дизайн-токены в `lib/core/theme/app_theme.dart`. Железные UX-правила манифеста (курсор basic, никакого дешёвого drag, премиум-переходы) действуют везде.

## Задача 1 — Онбординг первого запуска (ГЛАВНАЯ)

Сейчас новый юзер видит пустое тёмное окно и ни одной подсказки: C, V, I, Esc, Ctrl+scroll и сам глобальный хоткей — всё невидимо. Приветствие из кода ранее удалено (`main.dart` ~110: «greeting removed»), но вся проводка жива: `StaircaseState.isFirstRun / showWelcome / isWelcoming` (spatial_zoom_engine.dart), prefs `slate_onboarded` / `slate_welcomed` (local_prefs.dart).

Сценарий, который надо построить:
1. Первый запуск → спокойный welcome-момент. Дизайн-фундамент УЖЕ лежит в `lib/ui/screens/preview_first_run.dart` (Fraunces-приветствие, живой графитовый штрих draw-on, paper grain) — переиспользуй его как основу, это принятое направление.
2. Welcome учит ОДНОЙ вещи: «Press <hotkey> — anywhere, anytime» с РЕАЛЬНЫМ хоткеем из `QuickCaptureController.hotkeyLabel` (на части машин фолбэк Ctrl+Alt+Space — не хардкодить «Alt+Space»).
3. Юзер сам нажимает хоткей и делает первый захват. Учти: при сфокуснутом Slate хоткей открывает in-app capture-сцену (`inAppCapture`), не оконный морф — онбординг должен красиво работать в обоих путях.
4. После первого захвата — показать, куда упала задача (инбокс/день), и на этом welcome завершён навсегда (`slate_welcomed`).
5. До первого захвата (`isFirstRun`) в пустых состояниях живут тихие подсказки-приглашения: день («C — capture a task»), неделя, инбокс («I — inbox»), переключение видов («V»). Не туториал-цирк с балунами — тихие строки-призраки в стиле пустых состояний.
6. Демо-данные: 4–5 задач на сегодня/завтра (с временами, чтобы легли на таймлайн) + пара мыслей в инбоксе — чтобы новичку было что потягать (drag), чекнуть и растянуть, почувствовать физику. Создавать через реальный движок (FFI), удаляемые как обычные задачи. Сам реши эталонный подход: помечать ли их визуально и как предложить «clear demo data».

Механику морфа окна и хоткея НЕ трогать — она вылизана семью раундами и работает.

## Задача 2 — Undo

Отмена для чекбокса и удаления задачи + Ctrl+Z. Сейчас случайный чек/делит необратим — для инструмента, куда человек выгружает голову, это провал доверия.
- Toast «Undone» в стиле Slate (никакого дефолтного Material SnackBar), спокойный, самоисчезающий.
- Механика восстановления: продумай через `TaskState` (lib/core/state/task_state.dart); для удаления реши сам — держать последний слепок задачи в Dart и пересоздавать через существующий FFI-путь допустимо, если восстанавливаются ВСЕ поля (день, время, теги, inbox-статус, done). Rust трогай только при реальной необходимости; помни закон ABI/DLL.

## Задача 3 — Тихая точка прогресса (счётчики без вины)

Сейчас: заголовок недели «4/13», на днях «0/1», бейдж «Inbox 26», возраст мыслей «1d/2d». По компасу продукта это дроби-упрёки («ты сделал 4 из 13»).
Найди эталонное решение «тихого прогресса»: 2–3 варианта (примеры направлений: молча заполняющаяся точка/кольцо; показывать только сделанное без знаменателя; цифры только на hover; для возраста мыслей — вообще без счётчика времени). Выбери сам наилучший и примени КОНСИСТЕНТНО во всех четырёх местах. Требование: пустой/несделанный день не должен ощущаться как долг. Обоснование выбора — одной строкой в отчёте.

## Задача 4 — Экспорт JSON

Пункт в трее (`lib/core/engine/tray_shell.dart`): «Export data…» → JSON всех задач в файл (в Documents; диалог сохранения — только если без новых тяжёлых зависимостей). Формат человекочитаемый и стабильный, полнота полей обязательна: заголовок, день, времена, теги, done, inbox, created. Источник — реши сам (FFI-экспорт из Rust или сериализация из TaskState); критерий — ни одно поле не теряется.

## Задача 5 — Crash-лог + «Report a problem»

- Dart: `runZonedGuarded` + `FlutterError.onError` → лог-файл (рядом с базой: `Documents/slate_data/logs/`), простая ротация (не расти бесконечно), в каждой записи версия приложения.
- Rust: panic hook (ремень поверх закона zero-panic) пишет в тот же каталог; помни — паника всё равно убьёт Flutter, hook только фиксирует след.
- Трей: пункт «Report a problem» → открывает папку логов в Explorer.
